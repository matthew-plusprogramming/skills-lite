# Review a plan

Read the original request and the proposed plan as an independent, read-only reviewer.

1. **Outcome and authority.** Can you state the observable result and exactly what approval permits? Flag any mismatch with the request or unresolved decision that changes scope.
2. **Weakest assumption.** Find the premise most likely to invalidate the approach. Look for existing evidence or suggest the smallest check that could disprove it.
3. **Proof.** Could every proposed check pass while the user still misses the outcome? Give a concrete counterexample if one exists. Ask for a check through the actual user workflow with an expected result. For larger work, check that each milestone produces something verifiable.
4. **Decision clarity.** Read the opening as if on a phone. Can the reader see the approval request, the tradeoff most likely to change their mind, and how success will be judged? Identify exactly what to move up, cut, or put behind a disclosure. Preserve details needed to execute or verify a consequential decision.

Return **Ready for human approval** or **Revise first**. Lead with the most consequential finding and its smallest fix. If the plan is sound, say why in one sentence. Keep optional edits distinct from blockers. The author summarizes what changed and waits for explicit human approval before implementation.
